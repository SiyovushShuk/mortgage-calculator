# Дополнение к ТЗ: Ипотечный калькулятор — v3 (правки)

Ниже три правки к уже реализованному калькулятору.

---

## 1. Баг: отображаются оба типа платежа одновременно

**Проблема:** сейчас на экране всегда показываются и аннуитетный,
и дифференцированный расчёт, даже если пользователь выбрал только один тип.

**Требуется:** показывать результат **только выбранного** типа платежа.

### Логика

- Пользователь выбирает тип платежа: `Аннуитетный` или `Дифференцированный`
  (переключатель/radio-button/select — то, что уже реализовано в форме)
- Блок результата должен рендерить **только** расчёт для выбранного типа
- Второй тип **не должен** отображаться, рассчитываться на экран или занимать место в UI,
  пока пользователь не переключится на него

```
Если Тип_платежа == "Аннуитетный":
    Показать блок с аннуитетным расчётом
    Скрыть/не рендерить блок дифференцированного расчёта

Если Тип_платежа == "Дифференцированный":
    Показать блок с дифференцированным расчётом (график/таблица по месяцам)
    Скрыть/не рендерить блок аннуитетного расчёта
```

*(Опционально, если нужно сравнение: можно добавить отдельную кнопку "Сравнить оба
варианта", которая по явному запросу пользователя покажет оба расчёта рядом —
но по умолчанию отображается только выбранный тип.)*

## 2. Форматирование чисел: разделение по разрядам

**Проблема:** большие числа отображаются слитно и плохо читаются,
например `20000000` вместо `20 000 000`.

**Требуется:** все числовые значения (сумма ипотеки, сумма взноса, тело кредита,
ежемесячный платёж, итоговая переплата и т.д.) должны отображаться
с разделением по 3 цифры с конца, через пробел.

### Примеры

| Как сейчас | Как должно быть |
|---|---|
| 20000000 | 20 000 000 |
| 4000000 | 4 000 000 |
| 176161 | 176 161 |
| 226666.67 | 226 666,67 |

### Технические детали

- Форматирование применяется **только к отображению** (в input-полях при выводе
  и в блоках результата) — само значение, участвующее в расчётах, должно оставаться
  обычным числом (без пробелов), чтобы не ломать математику
- Разделитель разрядов — пробел (стандарт для рублей/русской локали)
- Разделитель дробной части — запятая (например, `226 666,67`), округление до 2 знаков
  после запятой для денежных сумм
- В JS можно использовать `toLocaleString('ru-RU')`, например:
  ```js
  (20000000).toLocaleString('ru-RU') // "20 000 000"
  (226666.67).toLocaleString('ru-RU', { minimumFractionDigits: 2, maximumFractionDigits: 2 }) // "226 666,67"
  ```
- Важно: при вводе пользователем числа в поле форматирование не должно мешать
  вводу (не форматировать "на лету" каждый символ так, чтобы курсор прыгал) —
  форматирование лучше применять при потере фокуса поля (`onBlur`) либо только
  к выводимым (read-only) результатам, а не к самим input-полям ввода.

## 3. Ввод процентной ставки с одним знаком после запятой

**Проблема:** сейчас процентную ставку нельзя ввести дробным числом
(например, 18.5%, 20.4%, 0.5%) — только целые значения.

**Требуется:** поле ввода процентной ставки должно поддерживать
**один знак после запятой/точки**.

### Логика

- Допустимый формат: число с точностью до 0,1 (например: `18.5`, `20.4`, `0.5`, `12`, `9.9`)
- Разделитель дробной части в поле ввода — точка (`.`) либо запятая (`,`),
  в зависимости от того, что уже принято в остальной форме приложения —
  главное, чтобы было единообразно
- Шаг для числового поля (если используется `<input type="number">`) — `step="0.1"`
- Валидация: значение должно быть положительным, разумные границы
  (например, от 0,1 до 50% годовых — на усмотрение реализации)
- Это же значение (i = ставка/100/12) участвует в формулах расчёта без округления —
  округлять нужно только то, что видит пользователь (сами платежи), а не саму ставку

### Пример

- Пользователь вводит `18.5` → в расчёт идёт ставка **18,5% годовых**
  → месячная ставка i = 0,185 / 12 ≈ 0,015417
