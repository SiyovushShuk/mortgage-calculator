# Дополнение к ТЗ: Ипотечный калькулятор — v14 (баг: "Общая сумма выплат" не пересчиталась после фикса v13)

Продолжение бага из v13 — исправление было применено только к таблице по
месяцам, но не к сводному блоку "Было / Стало".

---

## Проблема

После исправления бага v13 (переплата в последний месяц) таблица по месяцам
стала верной: в последнем месяце "Тело" теперь равно остатку долга, остаток
после — ровно 0.

Но в блоке **"Было / Стало"** значение **"Общая сумма выплат"** для сценария
"С досрочным" всё ещё показывает старое, ошибочное число:

| | Показано сейчас | Должно быть |
|---|---|---|
| Переплата по процентам | 9 868 045,36 ¤ (верно) | 9 868 045,36 ¤ |
| **Общая сумма выплат** | **29 949 710,06 ¤ (неверно)** | **29 868 045,36 ¤** |

Проверка:
```
Тело_кредита + Переплата_с_доплатами = 20 000 000 + 9 868 045,36 = 29 868 045,36 ¤
```
Это и есть корректная "Общая сумма выплат" — а показанное число расходится
с ней ровно на 81 664,7 ¤ — то есть на ту же самую величину бага, который
уже исправили в таблице по месяцам.

## Причина

Похоже, что "Общая сумма выплат" в блоке "Было / Стало" считается **отдельно**
от таблицы по месяцам — какой-то самостоятельной формулой/переменной, которая
не была затронута фиксом v13 (например, что-то вроде "стандартный платёж ×
количество месяцев" без учёта того, что последний месяц по факту меньше
обычного).

## Требуется исправить

**"Общая сумма выплат" должна вычисляться одним из двух надёжных способов,
а не отдельной формулой:**

### Вариант А (рекомендуется) — сумма фактических платежей из Истории

```
Общая_сумма_выплат = Σ (Платёж_факт по каждому месяцу из Истории)
```

То есть взять ту же самую Историю (массив по месяцам), которая уже
используется для таблицы (и там уже исправлена в v13), и просуммировать
поле `Платёж_факт` (или `Основной_долг + Проценты + Доп_факт`) по всем
месяцам без дублирования логики расчёта в другом месте.

### Вариант Б — через уже готовые агрегаты

```
Общая_сумма_выплат = Тело_кредита + Переплата_по_процентам
```

где `Переплата_по_процентам` — тоже сумма `Проценты` из той же Истории.
(Здесь `Переплата_по_процентам` уже верна, значит проблема не в ней, а
именно в отдельном подсчёте "Общей суммы выплат", который надо привести
к этой же формуле.)

## Важно — общий принцип, чтобы не плодить похожие баги

Все итоговые/сводные цифры (переплата, общая сумма выплат, экономия и т.д.)
должны вычисляться **на основе одного и того же массива Истории** (после
применения фикса из v13), а не дублироваться отдельными формулами в разных
местах компонента. Если "Общая сумма выплат" и "Переплата по процентам"
считаются в разных функциях — стоит объединить их в одну общую функцию
подсчёта агрегатов из Истории, чтобы при следующем исправлении бага в
логике помесячной симуляции не пришлось искать все места, где что-то
считается заново вручную.

## Как протестировать

1. Тот же пример: 25 000 000 ¤, взнос 20%, ставка 24%, 240 мес., аннуитет,
   доп. платёж 300 000 ¤/мес.
2. Проверить, что в блоке "Было / Стало" для колонки "С досрочным":
   ```
   Общая сумма выплат = Тело_кредита + Переплата_по_процентам   (точное совпадение, без разницы в 81 664 ¤)
   ```
3. Проверить также колонку "Без досрочного" на всякий случай — там срок
   не пересчитывается по факту (n остаётся исходным), поэтому там,
   вероятно, бага нет, но стоит убедиться, что и там сумма сходится:
   ```
   Общая_сумма_выплат_без_доплат = Тело_кредита + Переплата_без_доплат
   ```
4. Повторить проверку на 2-3 других комбинациях входных данных
