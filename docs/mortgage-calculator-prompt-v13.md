# Дополнение к ТЗ: Ипотечный калькулятор — v13 (баг: переплата в последний месяц)

Критичный баг в расчётах на вкладке "Досрочное погашение с уменьшением срока
кредита" (и, вероятно, аналогичный баг в "уменьшением платежа" — см. проверку
ниже).

---

## Проблема (обнаружено на реальном расчёте)

Исходные данные: сумма ипотеки 25 000 000 ¤, взнос 20% → тело кредита
20 000 000 ¤, ставка 24% годовых, срок 240 мес., аннуитет, доп. платёж
300 000 ¤/мес.

В **последнем** месяце симуляции (43-й месяц в этом примере) обнаружено:

| Показатель | Значение |
|---|---|
| Остаток долга **перед** последним платежом | 315 506,78 ¤ |
| Проценты за последний месяц (315 506,78 × 0,02) | 6 310,14 ¤ — верно |
| **"Тело" (основной долг), показанное программой** | **397 171,49 ¤** ← ошибка |
| Должно быть (= остатку долга) | **315 506,78 ¤** |

**"Тело" не может быть больше, чем сам остаток долга перед этим платежом** —
но программа списала на 81 664,71 ¤ больше, чем реально было должно.

Эта ошибка "утекает" и в итоговые суммы:
```
Тело_кредита + Переплата_с_доплатами = 20 000 000 + 9 868 045,36 = 29 868 045,36 ¤
Показанная "Общая сумма выплат" = 29 949 710,06 ¤

Разница = 29 949 710,06 − 29 868 045,36 = 81 664,70 ¤   ← ровно та же переплата
```

## Причина

В обычных (не последних) месяцах платёж рассчитывается по стандартной
формуле аннуитета/дифференцированного платежа. Но **в последний месяц**
симуляции остаток долга уже меньше, чем "стандартный" основной долг по
формуле — а программа не проверяет и не "подрезает" платёж под фактический
остаток. В результате последний месяц гасит больше, чем реально должно
было остаться, — платёж в последний месяц завышен.

---

## Требуется исправить

### Для режима "уменьшение срока" (промпт v5)

В цикле помесячной симуляции — **до** вычитания из остатка — добавить
проверку: если рассчитанный основной долг (или платёж целиком) больше,
чем сам остаток, нужно **урезать** его ровно до размера остатка, а не
списывать "с запасом".

**Исправленная логика (аннуитетный):**

```
Остаток = S
P = аннуитетный платёж (по исходной формуле)
Месяц = 0

Пока Остаток > 0:
    Месяц += 1
    Проценты = Остаток × i
    Основной_долг = min(P − Проценты, Остаток)        // ← ИСПРАВЛЕНИЕ: не больше остатка
    Доп_факт = min(Доп_платёж, Остаток − Основной_долг)
    Платёж_факт = Основной_долг + Проценты + Доп_факт  // фактический платёж в этом месяце
    Остаток = Остаток − Основной_долг − Доп_факт
    Если Остаток < 0: Остаток = 0
```

**Исправленная логика (дифференцированный):**

```
Остаток = S
Осн = S / n
Месяц = 0

Пока Остаток > 0:
    Месяц += 1
    Проценты = Остаток × i
    Основной_долг = min(Осн, Остаток)   // это уже было верно в исходном промпте v5
    Доп_факт = min(Доп_платёж, Остаток − Основной_долг)
    Остаток = Остаток − Основной_долг − Доп_факт
    Если Остаток < 0: Остаток = 0
```

*(Для дифференцированного платежа эта защита уже была заложена в исходном
промпте v5 — баг, судя по всему, реализован только в ветке аннуитетного
расчёта. Нужно явно перепроверить код и убедиться, что `min(...)` там
действительно присутствует и работает.)*

### Важно — сохранить в таблице/истории фактический платёж, а не "теоретический"

В сохранённой Истории (для таблицы по месяцам и графика) в последний месяц
должны быть именно **фактические** значения (`Основной_долг`, `Платёж_факт`),
рассчитанные с учётом `min(...)`, а не изначальный "теоретический" платёж
по формуле — иначе баг снова проявится визуально в таблице, даже если
итоговые суммы уже посчитаны верно.

---

## Проверить также режим "уменьшение платежа" (промпт v7)

В этом режиме срок фиксирован (n месяцев), поэтому последний месяц (n-й)
как раз тот, где `Месяцев_осталось = 1`. Формула аннуитета на 1 месяц
сама по себе уже должна корректно давать платёж, равный остатку + проценты
(это математическое свойство формулы аннуитета при n=1), — но стоит явно
протестировать этот сценарий на реальных числах и убедиться, что нет
похожей ошибки округления или "утечки" в последнем месяце.

---

## Как протестировать исправление

1. Взять тот же пример (25 000 000 ¤, взнос 20%, ставка 24%, 240 мес.,
   аннуитет, доп. платёж 300 000 ¤/мес.)
2. Убедиться, что в последнем месяце **"Тело" ровно равно остатку долга
   перед этим платежом**, а **Остаток после последнего платежа = 0** (не
   отрицательный и не больше нуля)
3. Проверить, что:
   ```
   Тело_кредита + Переплата_с_доплатами = Общая_сумма_выплат   (точное равенство, без разницы в 81 664 ¤ или подобной)
   ```
4. Повторить проверку с другими комбинациями сумм/ставок/сроков/доп.
   платежей, особенно с "некруглыми" числами, где остаток вряд ли
   поделится ровно на стандартный платёж без остатка
