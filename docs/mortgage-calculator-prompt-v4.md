# Дополнение к ТЗ: Ипотечный калькулятор — v4 (правки)

Ниже две правки к уже реализованному калькулятору.

---

## 1. Форматирование чисел прямо во время ввода (live-formatting)

**Проблема:** в v3 форматирование (разделение по разрядам) применялось только
к выводу результатов. Но при вводе суммы в само поле — число снова
отображается слитно (`20000000`), и это неудобно читать даже во время набора.

**Требуется:** поля ввода сумм (сумма ипотеки, сумма взноса — в режиме "Сумма",
и т.д.) должны показывать разделённое по разрядам число **прямо во время
набора**, не дожидаясь потери фокуса.

### Как это правильно реализовать (без "прыгающего курсора")

Наивное форматирование на каждый `onChange` часто ломает курсор — он
уезжает в конец поля при вводе цифр в середине числа. Нужно делать так:

1. Хранить в состоянии (state) **чистое число** без пробелов (например, `20000000`)
   — именно оно участвует в расчётах.
2. В `onChange`:
   - Убрать из введённого значения все нецифровые символы, кроме нужных
     (для сумм — только цифры)
   - Сохранить очищенное число в state
3. В `value` инпута передавать **отформatированную** версию числа
   (`20000000` → `"20 000 000"`) через `toLocaleString('ru-RU')`
4. Чтобы курсор не улетал в конец при вводе не в конце строки — вычислять
   позицию курсора **до** и **после** форматирования и восстанавливать её
   вручную через `ref.current.setSelectionRange(...)`, учитывая разницу
   в количестве добавленных пробелов слева от курсора.

### Пример логики (React, псевдокод)

```jsx
function handleAmountChange(e) {
  const input = e.target;
  const rawValue = input.value.replace(/\D/g, ''); // только цифры
  const cursorPosBefore = input.selectionStart;
  const digitsBeforeCursor = input.value.slice(0, cursorPosBefore).replace(/\D/g, '').length;

  setAmount(Number(rawValue)); // чистое число в state — для расчётов

  // после ре-рендера с новым отформатированным значением
  requestAnimationFrame(() => {
    const formatted = input.value; // уже новое отформатированное значение
    let digitsSeen = 0;
    let newPos = formatted.length;
    for (let i = 0; i < formatted.length; i++) {
      if (/\d/.test(formatted[i])) digitsSeen++;
      if (digitsSeen === digitsBeforeCursor) { newPos = i + 1; break; }
    }
    input.setSelectionRange(newPos, newPos);
  });
}
```

```jsx
<input
  type="text"
  inputMode="numeric"
  value={amount.toLocaleString('ru-RU')}
  onChange={handleAmountChange}
/>
```

### Важно

- `type="text"` вместо `type="number"` — потому что `<input type="number">`
  не позволяет вставлять пробелы внутри значения
- `inputMode="numeric"` — чтобы на мобильных устройствах открывалась цифровая клавиатура
- То же самое применяется ко всем полям с суммами (сумма ипотеки, сумма взноса
  в режиме "Сумма"). Поля с процентами и сроком в разделении разрядов не нуждаются.

## 2. Расчёт по кнопке "Посчитать", а не в реальном времени

**Проблема:** сейчас расчёт пересчитывается на каждое изменение любого поля.
Нужно, чтобы расчёт запускался только по явному действию пользователя.

**Требуется:** добавить кнопку **"Посчитать"**. Результат (платёж, график,
переплата и т.д.) должен обновляться **только после нажатия** на эту кнопку,
а не при каждом изменении инпутов.

### Логика

- Изменение любого поля ввода (сумма, взнос, ставка, срок, тип платежа)
  **не запускает** пересчёт автоматически
- Все данные из формы собираются и передаются в функцию расчёта **только**
  по клику на кнопку "Посчитать"
- Пока пользователь не нажал кнопку — блок результата либо:
  - не отображается вообще (до первого расчёта), либо
  - показывает последний рассчитанный результат (не обновляется "живьём"
    при дальнейшем изменении полей, пока не нажата кнопка снова)

### UX-рекомендации

- Кнопку "Посчитать" сделать заметной (primary-стиль), расположить сразу
  под/рядом с формой ввода
- Если после расчёта пользователь поменял любое поле — стоит показать
  небольшую подсказку/индикатор ("Данные изменены — нажмите «Посчитать»
  для обновления результата"), чтобы не запутать пользователя, что
  видимый результат уже не соответствует введённым данным
- Кнопка должна быть неактивна (disabled) или показывать ошибку,
  если форма не прошла валидацию (пустые поля, некорректные значения)

## 3. Ежемесячный платёж должен быть визуально главным элементом результата

**Проблема:** сумма ежемесячного платежа сейчас теряется среди остальных
цифр (переплата, тело кредита и т.д.), хотя это самое важное число для
пользователя.

**Требуется:** сумма ежемесячного платежа должна быть **по центру** блока
результата и визуально выделяться на фоне остальных данных.

### UX-требования

- Блок с суммой платежа — **по центру** (текст выровнен по центру,
  сам блок центрирован по горизонтали в контейнере результата)
- Крупный размер шрифта — заметно больше, чем у остальных цифр
  (переплата, тело кредита, сумма взноса и т.д.), например в 2–3 раза
- Можно выделить дополнительно: жирным начертанием, акцентным цветом
  (например, основным цветом приложения), небольшой подписью сверху/снизу
  мелким шрифтом — "Ежемесячный платёж"
- Остальные цифры (переплата, общая сумма выплат, тело кредита) располагаются
  вокруг/под этим блоком более мелким и нейтральным шрифтом — как
  вспомогательная информация
- Для **дифференцированного** платежа, где сумма меняется каждый месяц,
  по центру аналогично крупно показывать **первый платёж** (самый большой)
  с подписью вида "Платёж в 1-м месяце", а остальные месяцы — в таблице/графике
  ниже, не такими крупными

### Пример визуальной иерархии (сверху вниз)

```
        Ежемесячный платёж
        176 161 ₽              ← крупно, по центру, жирным, акцентный цвет

Тело кредита: 16 000 000 ₽     ← мельче, обычным шрифтом
Переплата по процентам: 26 278 640 ₽
Итого выплат: 42 278 640 ₽
```
