# Дополнение к ТЗ: Ипотечный калькулятор — v10 (деплой: Docker + Vercel + GitHub Pages)

Настроить проект так, чтобы его можно было запустить тремя способами:
1. Локально/на своём сервере — **одной командой через Docker**
2. Бесплатно на **Vercel**
3. Бесплатно на **GitHub Pages**

Проект — фронтенд на React (предполагается сборка через Vite; если используется
Create React App — везде заменить папку сборки `dist` на `build`, остальное
без изменений).

---

## 1. Docker — запуск одной командой

### Dockerfile

Создать файл `Dockerfile` в корне проекта:

```dockerfile
# Этап 1 — сборка приложения
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Этап 2 — раздача собранной статики через nginx
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### nginx.conf

Нужен для корректной работы React Router (если используется) — чтобы обновление
страницы не давало 404:

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### docker-compose.yml

```yaml
services:
  calculator:
    build: .
    ports:
      - "8080:80"
    restart: unless-stopped
```

### Команда запуска

Всё, что нужно для запуска на любом сервере с установленным Docker:

```bash
docker-compose up -d --build
```

Приложение будет доступно на `http://<адрес_сервера>:8080`.

### Требования на сервере

- Установленные Docker и Docker Compose (ставятся одной командой на большинстве
  дистрибутивов Linux)
- Открытый порт 8080 (или другой на выбор — поменять в `docker-compose.yml`)
- Домен не обязателен для старта, можно зайти по IP:порт; для HTTPS и домена
  позже можно добавить reverse-proxy (например, Traefik или Caddy) — это
  отдельная доработка, не входит в этот пункт

## 2. Деплой на Vercel

Docker для Vercel не нужен — платформа сама собирает и раздаёт статику.

### Что нужно

- Файл `vercel.json` в корне проекта (нужен, если используется React Router,
  чтобы все маршруты корректно вели на `index.html`):

```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

### Как задеплоить

1. Залить проект в GitHub-репозиторий
2. Зайти на vercel.com → New Project → выбрать репозиторий
3. Vercel автоматически определит React/Vite-проект, команда сборки
   (`npm run build`) и папка вывода (`dist`) подставятся сами — можно
   не трогать настройки
4. Нажать Deploy — через минуту будет публичная ссылка вида
   `mortgage-calculator.vercel.app`
5. При каждом новом commit в GitHub — Vercel автоматически пересобирает
   и обновляет деплой

## 3. Деплой на GitHub Pages

### Что нужно

1. Установить пакет для деплоя:
```bash
npm install --save-dev gh-pages
```

2. В `package.json` добавить:
```json
{
  "homepage": "https://<твой-username>.github.io/<название-репозитория>",
  "scripts": {
    "predeploy": "npm run build",
    "deploy": "gh-pages -d dist"
  }
}
```
*(для Vite; если Create React App — `-d build` вместо `-d dist`)*

3. Если используется Vite — в `vite.config.js` указать базовый путь:
```js
export default {
  base: '/<название-репозитория>/',
}
```
*(без этого страница будет открываться "белым экраном", т.к. пути к JS/CSS
файлам будут неправильными)*

### Как задеплоить

```bash
npm run deploy
```

Эта команда соберёт проект и запушит его в отдельную ветку `gh-pages` — GitHub
сам поднимет сайт по адресу `https://<username>.github.io/<репозиторий>`.

Дополнительно нужно один раз включить GitHub Pages в настройках репозитория:
`Settings → Pages → Source → выбрать ветку gh-pages`.

## Итог: что в каком случае использовать

| Способ | Когда использовать |
|---|---|
| **Docker** | Свой VPS, полный контроль, планы на бэкенд/бота в будущем |
| **Vercel** | Быстрее и проще всего для чистого фронтенда, автодеплой по git push |
| **GitHub Pages** | Бесплатно, просто, без своего сервера, но чуть больше ручной настройки путей |

Все три способа могут работать **параллельно** — ничего не мешает держать
код в одном репозитории и одновременно раздавать его и на Vercel,
и на GitHub Pages, и через свой Docker на VPS.

## 4. README.md

Добавить в корень проекта файл `README.md`, описывающий, как и где запускать
приложение — чтобы через полгода не пришлось вспоминать все детали заново
(или объяснять их кому-то ещё).

### Что должно быть в README

- Краткое описание проекта (что это за калькулятор, какой функционал)
- **Запуск локально для разработки:**
  ```bash
  npm install
  npm run dev
  ```
- **Запуск через Docker (свой сервер):**
  ```bash
  docker-compose up -d --build
  ```
  приложение будет доступно на `http://localhost:8080` (или на адресе сервера)
- **Деплой на Vercel** — короткая инструкция (подключить репозиторий на
  vercel.com, дальше всё автоматически) + ссылка на актуальный деплой,
  если он уже есть
- **Деплой на GitHub Pages:**
  ```bash
  npm run deploy
  ```
  + ссылка на актуальную страницу, если уже задеплоено
- Список основных технологий (React, Vite, и т.д.)
- Ссылка на этот файл ТЗ (или все промпты v1–v10) — например, в папку `/docs`
  внутри репозитория, чтобы вся история требований к калькулятору была
  под рукой вместе с кодом, а не потерялась в переписке
