# Дополнение к ТЗ: Ипотечный калькулятор — v15 (баг: сводка не отражает реальное досрочное закрытие в режиме "уменьшение платежа")

Баг на вкладке "Досрочное погашение с уменьшением платежа" (промпт v7):
математика расчёта верна, но сводные показатели не соответствуют
фактическому результату симуляции.

---

## Важное уточнение логики (перед фиксом)

При **фиксированной ежемесячной доплате** кредит с пересчётом платежа
(режим "уменьшение платежа") **тоже может закрыться раньше исходного
срока n** — это математически нормально и ожидаемо, если доплата
достаточно большая: пересчитанный минимальный платёж каждый месяц падает,
но заёмщик всё равно вносит полную доплату сверху, поэтому долг гасится
быстрее, чем "по расписанию" на n месяцев.

**Это не баг сам по себе** — баг в том, что сводные показатели в интерфейсе
не отражают этот факт и продолжают показывать исходный срок n, как будто
кредит идёт по плану все 240 месяцев.

## Проблема 1 — "Срок кредита" в блоке "Было / Стало" не обновляется

**Показано сейчас:**

| | Без досрочного | С досрочным |
|---|---|---|
| Срок кредита | 240 мес | **240 мес** ← неверно |

**По факту** (видно в таблице по месяцам) кредит с доплатами закрылся на
**67-м месяце** (последний ненулевой платёж — 216,69 ¤, дальше остаток = 0).

**Требуется:** "Срок кредита" в колонке "С досрочным" должен показывать
**фактический номер месяца, на котором Остаток впервые достиг 0** — то
есть номер последней строки Истории, где был ненулевой платёж, а не
исходный n.

```
Факт_срок_с_доплатами = номер последнего месяца из Истории, где Остаток_после > 0 (плюс этот месяц включительно)
// то есть месяц, на котором Остаток впервые стал 0
```

## Проблема 2 — "Ежемесячный платёж: ... → 0 ¤" показывает технический ноль вместо реального последнего платежа

**Показано сейчас:** "403 481,63 ¤ → 0 ¤"

**Требуется:** конечное значение должно быть **последним фактическим,
ненулевым платежом** из Истории (в этом примере — **216,69 ¤**, платёж
67-го месяца), а не "0", который является лишь техническим заполнением
пустых строк после закрытия кредита.

```
Финальный_платёж_факт = Платёж из Истории за месяц Факт_срок_с_доплатами (последний ненулевой)
```

Подпись можно изменить на что-то вроде:
"Платёж будет снижаться и в последний, {Факт_срок_с_доплатами}-й месяц,
составит {Финальный_платёж_факт} ¤ — кредит будет полностью погашен
раньше срока."

## Проблема 3 — лишние нулевые строки в таблице по месяцам

**Показано сейчас:** таблица продолжается до месяца 240, где после
фактического закрытия кредита (67-й месяц) все строки — просто нули.

**Требуется:** таблица (и график) не должны показывать месяцы **после**
фактического закрытия кредита — то есть если Остаток достиг 0 на 67-м
месяце, строки с 68 по 240 просто **не включаются** в отображаемую
Историю/таблицу/график (как это уже сделано в режиме "уменьшение срока",
где таблица тоже заканчивается в момент закрытия, без пустых нулевых
строк дальше).

```
Отображаемая_История = История[0 : Факт_срок_с_доплатами]   // обрезать хвост из нулей
```

## Общий принцип (перекликается с v14)

Если кредит с доплатами закрывается раньше n (в любом из двух режимов
досрочного погашения) — весь интерфейс должен консистентно отражать
**фактический** срок закрытия, а не исходный n:
- Заголовок/подпись "Срок кредита"
- Таблица по месяцам (без лишних нулевых строк)
- График (не должен рисовать линию до 240 месяца, если кредит закрылся на 67-м)
- Любые другие места, где упоминается срок или платёж "в последний месяц"

## Проблема 4 — тип платежа игнорируется в симуляции режима "уменьшение платежа"

**Обнаружено:** при выбранном типе платежа **"Дифференцированный"** на
вкладке "Досрочное погашение с уменьшением платежа" реальный помесячный
расчёт всё равно идёт **по формуле аннуитета** — тип платежа не
передаётся/не учитывается внутри симуляции этой вкладки.

### Доказательство

При S = 20 000 000 ¤, i = 0,02, n = 240, Доп_платёж = 300 000 ¤/мес.,
тип = Дифференцированный — 1-й месяц должен считаться так:

```
Осн_текущий = 20 000 000 / 240 = 83 333,33 ¤
Проценты = 20 000 000 × 0,02 = 400 000 ¤
Платёж = 83 333,33 + 400 000 = 483 333,33 ¤
Остаток = 20 000 000 − 83 333,33 − 300 000 = 19 616 666,67 ¤
```

**Показано в таблице по факту:** Платёж = 403 481,63 ¤, Остаток =
19 696 518,37 ¤ — это **в точности** совпадает с расчётом для аннуитета
(см. предыдущий тест той же вкладки с типом "Аннуитет") — то есть выбор
дифференцированного типа никак не повлиял на расчёт.

Дополнительно это же видно в блоке "Было / Стало": колонка "Без
досрочного" (базовый расчёт без симуляции) правильно показывает
дифференцированные цифры **"483 333,33 ¤ → 85 000 ¤"**, а колонка
"С досрочным" (результат симуляции) — аннуитетные цифры
**"403 481,63 ¤ → 0 ¤"**. То есть тип платежа корректно используется
для базового расчёта (без доплат), но теряется при передаче в саму
функцию помесячной симуляции для вкладки "уменьшение платежа".

### Требуется исправить

Функция помесячной симуляции для режима "уменьшение платежа" (см. v7)
должна принимать выбранный тип платежа как параметр и использовать
**соответствующую** формулу пересчёта на каждый месяц:

```
Если Тип_платежа == "Аннуитетный":
    P_текущий = Остаток × [ i × (1+i)^Месяцев_осталось ] / [ (1+i)^Месяцев_осталось − 1 ]
    Проценты = Остаток × i
    Основной_долг = P_текущий − Проценты

Если Тип_платежа == "Дифференцированный":
    Осн_текущий = Остаток / Месяцев_осталось
    Проценты = Остаток × i
    Платёж = Осн_текущий + Проценты
    Основной_долг = Осн_текущий
```

**Проверить также вкладку "уменьшение срока" (v5)** на этот же класс
бага — судя по прошлому тесту (дифференцированный + уменьшение срока)
там всё считалось верно, но стоит явно перепроверить код: не захардкожена
ли где-то формула аннуитета вместо использования выбранного типа, раз
подобный баг уже нашёлся в соседней вкладке.

### Как протестировать (проблема 4)

1. Те же исходные данные (25 000 000 ¤, взнос 20%, ставка 24%, 240 мес.,
   доп. платёж 300 000 ¤/мес.), тип — Дифференцированный, вкладка
   "уменьшение платежа"
2. Убедиться, что 1-й месяц в таблице показывает **Платёж = 483 333,33 ¤**,
   **Тело = 83 333,33 ¤** (а не 403 481,63 / 3 481,63, как для аннуитета)
3. Убедиться, что блок "Было / Стало" показывает одинаковый **формат**
   чисел (дифференцированный) в обеих колонках — "Без досрочного" и
   "С досрочным" — а не разные типы расчёта в одной таблице

## Проблема 5 — таблица "График платежей" не отображается для аннуитета на вкладке "Без доп. платежей"

**Обнаружено:** на вкладке "Без доп. платежей" при типе платежа
**"Аннуитет"** таблица/график по месяцам вообще не отображается — виден
только блок "Итоги" (ежемесячный платёж, итого выплат, переплата, тело
кредита).

При этом для типа **"Дифференцированный"** на той же вкладке ("Без доп.
платежей") таблица "График платежей (таблица)" отображается корректно
и с верными цифрами (проверено ранее).

### Требуется исправить

Таблица/график по месяцам на вкладке "Без доп. платежей" должна
отображаться **для обоих типов платежа одинаково** — она особенно полезна
именно для аннуитета, чтобы показать, как соотношение "проценты/тело"
меняется от месяца к месяцу при неизменном общем платеже (это как раз
наглядно иллюстрирует саму суть аннуитетного платежа).

Скорее всего, в коде рендер этой таблицы завязан на условие, специфичное
для дифференцированного типа (например, `if (тип === 'дифференцированный')
{ показать таблицу }`), вместо того чтобы показывать её независимо от
типа платежа, различаясь только в том, как вычисляется каждая строка
Истории (см. формулы п.4.1 и п.4.2 из сводной спецификации).

### Как протестировать (проблема 5)

1. Выбрать тип "Аннуитет", вкладка "Без доп. платежей", любые исходные
   данные (например, 25 000 000 ¤, взнос 20%, ставка 24%, 240 мес.)
2. Убедиться, что таблица "График платежей (таблица)" отображается
   так же, как и при дифференцированном типе — с колонками Месяц,
   Платёж, Тело, Проценты, Остаток до, Остаток после
3. Проверить, что для аннуитета столбец "Платёж" **одинаков** во всех
   строках (в отличие от дифференцированного, где он уменьшается), а
   "Тело" и "Проценты" меняются от месяца к месяцу
4. Проверить последнюю строку (240-й месяц) — Остаток после должен
   быть ровно 0

## Как протестировать (проблемы 1–3, режим "уменьшение платежа")

1. Тот же пример: 25 000 000 ¤, взнос 20%, ставка 24%, 240 мес., аннуитет,
   доп. платёж 300 000 ¤/мес., режим "уменьшение платежа"
2. Убедиться, что "Срок кредита" в колонке "С досрочным" показывает
   **67 мес** (а не 240)
3. Убедиться, что "Ежемесячный платёж" в сводке показывает переход
   к **216,69 ¤** (реальный последний платёж), а не к 0
4. Убедиться, что таблица по месяцам заканчивается на 67-й строке,
   без нулевых строк дальше
5. Проверить график — линия должна визуально заканчиваться на 67-м
   месяце (или годах), а не продолжаться плоской нулевой линией до
   конца исходного срока
6. Повторить с меньшей доплатой (например, 20 000 ¤/мес.) — в этом
   случае кредит может закрыться ближе к исходному сроку n или даже
   не закрыться раньше него вовсе (если доплата слишком мала для
   этого при данной ставке) — стоит проверить оба случая: доплата,
   вызывающая раннее закрытие, и доплата, недостаточная для этого
